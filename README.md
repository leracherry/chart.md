# chart.md

**Charts for README.md.** Charts belong in Markdown too.

Generate static SVG charts from Markdown tables using TypeScript.

![Bundle size bar chart](.github/charts/bundle-size.svg)

## Quick start

Milestone 3 supports vertical bars, horizontal bars, and line charts, with up to
six numeric series per chart. Chart blocks in Markdown compile into named SVG files. The first npm release is prepared as `0.1.0`. You can also run from this checkout.

Use Node.js 22.13+ or 24+ and pnpm 10.17.1.

```sh
pnpm install --frozen-lockfile
pnpm build
node packages/cli/dist/index.js build README.md
```

This README is a working example. Its chart source is:

```chart id="bundle-size"
type: bar
title: Bundle size
unit: KB

| Package | Size |
| --- | ---: |
| Core | 18 |
| CLI | 31 |
| Adapter | 24 |
```

The command writes `.github/charts/bundle-size.svg`. Embed it with:

```md
![Bundle size](./.github/charts/bundle-size.svg)
```

See [the multiple-chart example](examples/readme/README.md) for a document with
both explicit and title-derived IDs. See [the chart engine examples](examples/engine/README.md)
for line charts, horizontal bars, grouped bars, and signed values.


### Build a README

`build` reads every top-level `chart` fence in one Markdown file and creates the
output directory recursively. The default is `.github/charts` relative to the
current directory. Custom output paths are also relative to the current directory,
even when the input lives elsewhere. Image references in Markdown must be relative
to the Markdown file itself. The source document is never modified.

Every chart is parsed and rendered, and every existing destination is checked,
before writing starts. Invalid charts or duplicate IDs leave existing output
unchanged. A document without charts succeeds without creating a directory.

Generated SVGs have a `Generated by chartmd build` comment. Rebuilding replaces
these files when their content changes and preserves unchanged files and their
modification times. Existing files without that comment and symlink destinations
are rejected. Each changed SVG is replaced atomically; a filesystem error during
a multi-chart write can leave some charts updated. Removed or renamed charts are
not deleted automatically. Use separate output directories for documents whose
chart IDs overlap.

### Render one chart

`render` accepts a chart body or a document containing exactly one chart fence.
It defaults to `chart.svg`. Its output directory must already exist, and existing
files are preserved. Choose a new output path or remove the old SVG to regenerate.

Errors go to stderr with a nonzero exit code. Build diagnostics include the source
filename and original source line when available.

## Chart IDs

Use `chart id="bundle-size"` to keep a filename independent of its title and
position. IDs contain 1–80 lowercase ASCII letters or digits, with single hyphens
between groups. Path separators, leading/trailing hyphens, and reserved device
names such as `con` are rejected.

Without an explicit ID, the title becomes a slug: `Bundle size` → `bundle-size`,
`Café latency` → `cafe-latency`. Slugs are truncated to 80 characters. If a title
is absent, has no ASCII letters or digits after normalization, or produces a
reserved name, the fallback is `chart-1`, `chart-2`, etc., based on chart order.
Use an explicit ID to keep these fallback filenames stable when reordering charts.

Duplicate IDs are errors, including collisions between explicit IDs and slugs.
Resolve a collision by adding distinct explicit IDs to the chart fences.

## Syntax and current limits

- Top-level backtick and tilde fences are accepted, with up to three leading
  spaces. Charts inside other fences or standalone HTML comments are ignored.
  Fences inside blockquotes, lists, indented code, and HTML containers are not a
  supported input format. The only supported fence option is `id="..."`.
- `type:` is required: `bar`, `horizontal-bar`, or `line`. Optional `title:`,
  `unit:`, `x:`, and `y:` values are plain text, with no YAML quoting or nesting.
  `x` and `y` set display captions for the physical axes; they do not select data
  columns. Captions default to table headers (or `Value` for multiple series).
  The unit is appended to the numeric axis caption. Unknown and duplicate keys
  are errors.
- Tables require 2–7 columns, a header, a separator, and 1–40 data rows.
  Each numeric column is a series, and series names must be unique.
  Every row must start and end with `|`. Separator cells use at least three dashes
  and optional alignment colons. Escaped pipes and inline Markdown are not parsed.
- The first column contains labels; all remaining columns contain finite decimal or
  scientific-notation numbers. Negative values and zero are supported. Nonzero
  magnitudes must be between `1e-9` and `1e12`; commas and units in cells are rejected.
- SVGs use a white background, distinct series colors, and a shared zero-inclusive
  numeric scale with ticks at multiples of 1, 2, or 5 times a power of ten.
  Multiple series receive legends. Bars are grouped, not stacked. Lines use
  markers and distinct dash patterns; all categories are equally spaced in source
  order, including numeric-looking labels. Missing numeric cells are errors.
- Numeric labels use compact `k`, `M`, `B`, and `T` suffixes or scientific notation
  for small values. Precise input values remain in SVG descriptions and titles.
  Single-series bars show values; multiple-series bars and lines keep values in
  descriptions and point titles to avoid clutter.
- Long category labels and headings are shortened visually; full text remains
  in accessible descriptions and SVG titles. Charts expand to fit larger datasets.
- Output is deterministic and contains no scripts, network references, or browser
  dependencies. Glob inputs, configuration, watch mode, and publishing are planned
  for later milestones.

## Programmatic API

```ts
import {
  parse,
  parseDocument,
  render,
  type ChartDefinition,
} from '@chartmd/core';

// Parse a single chart body or one-chart document.
const chart: ChartDefinition = parse(source);
const svg: string = render(chart);

// Parse fenced charts from a whole Markdown document.
for (const { id, line, chart } of parseDocument(markdown)) {
  // id is safe for an SVG filename; line is the opening fence's source line.
  const svg = render(chart);
}
```

`parseDocument` returns an empty array for a document with no charts. `render`
validates a chart definition and returns standalone SVG. Core has no filesystem
or browser dependency. You can also construct a definition directly:

```ts
const chart: ChartDefinition = {
  type: 'bar',
  title: 'Bundle size',
  unit: 'KB',
  labels: ['Core', 'CLI'],
  series: [{ name: 'Size', values: [18, 31] }],
};
```

### API migration from Milestone 2

`ChartDefinition.series` is now an array, including for a single series. Wrap old
`{ name, values }` objects in an array. `parse` now includes inferred `x` and `y`
axis captions. Existing Markdown chart sources continue to work.

## Development

```sh
pnpm build
pnpm test
pnpm typecheck
pnpm lint
pnpm format:check
```

`pnpm test` builds the packages and runs parser, document, renderer snapshot,
and CLI integration tests. `pnpm test:watch` builds once; run `pnpm build` after
changing package source to refresh the CLI used by integration tests. Use
`pnpm format` to apply formatting.

- `packages/core` — parser, document extraction, chart model, and SVG renderer.
- `packages/cli` — argument validation, file input, and SVG output.
- `tests` — unit, snapshot, and integration tests.
- `examples/basic` — single-chart render example.
- `examples/readme` — multiple-chart build example.
- `examples/engine` — line, horizontal, grouped, and signed-data examples.

CI validates Node.js 22 and 24. Run `pnpm changeset` for user-facing changes;
see [.changeset/README.md](.changeset/README.md). See [release instructions](.changeset/README.md) for npm publishing.
